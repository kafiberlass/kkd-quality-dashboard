# Требования и критерии приёмки

## Назначение

Страница ККД помогает руководителю быстро оценить качество целей и ключевых результатов выбранного подразделения, сравнить прогон с предыдущим успешным и перейти к проблемам для исправления.

## Функциональность

- Получать оргструктуру из `GET /api/meta`, историю через `GET /api/runs`.
- Смена подразделения и прогона должна обновлять сводку и список без перезагрузки.
- Получать метрики через `GET /api/kkd/summary?run_id=&unit_id=`. Числа и оценку направления брать из API, не вычислять на клиенте.
- Показывать сравниваемый прогон и дату. При `previous`/`delta = null` писать «Нет данных для сравнения».
- Показывать счётчики `new`, `persisting`, `resolved`; клик по счётчику открывает список с соответствующим фильтром.
- Получать проблемы через `GET /api/kkd/issues` с серверными фильтрами и пагинацией.
- Открывать `GET /api/kkd/issues/{id}?run_id=` с описанием, фактическим и ожидаемым значениями, рекомендацией и историей.
- Обрабатывать неуспешный прогон, отсутствие сравнения, подразделение без целей, загрузку, сетевую ошибку и пустой результат.

## Критерии приёмки

- Корпоративная тема Ant Design 5, базовый текст 14/22, тёплый фон, десктопная раскладка от 1280 px.
- Направление дельты передаётся значком, текстом и цветом; цвет не несёт смысл один.
- Важность и статус проблемы подписаны словами.
- Поддерживается клавиатурное взаимодействие, семантические кнопки и подписи контролов.
- `docker compose up --build` поднимает mock API и приложение.
- API URL задаётся через переменную окружения.
- README содержит запуск одной командой; спецификация документирует работу с ИИ.
